# 中断控制器回放页（TypeScript，无真实硬件）

一个纯模拟的中断控制器：可配置 **1～8 条中断线**，每条有唯一 ID、优先级、
边沿/电平模式与处理程序所需 tick；事件可在指定 tick 触发（raise）、撤销电平
（lower）、屏蔽（mask）或解除屏蔽（unmask）。回放输出至多 **500 tick** 的
执行栈、进入/抢占/恢复证据与待处理位证据，页面时间轴、逐 tick 表格与日志
**引用同一条轨迹**。

## Tick 内固定顺序（状态机）

每个 tick 严格按以下顺序推进：

1. **阶段 A 应用事件**：同一 tick 的多个事件按 JSON 列表顺序生效。
2. **阶段 B 处理上一 tick 的完成**：栈顶处理程序在上一 tick 执行完最后一个
   tick 后，于本 tick 出栈（因此「完成」与「执行最后一拍」分属相邻两个 tick）。
3. **阶段 C 调度/抢占**：
   - 栈空：取优先级最高的可运行待处理线进入；
   - 栈非空：仅**严格更高**优先级的待处理线可抢占当前程序；
   - **同优先级**永不抢占，按待处理时刻 `since`、再按 ID 排队等待。
4. **阶段 D 执行**：栈顶处理程序执行 1 tick；被抢占而挂起的帧此 tick
   **不执行、不消耗 handlerTicks**。

## 语义要点

- **边沿线**：屏蔽期间触发保留 **1 个待处理位**，屏蔽期内重复触发**合并**
  （轨迹中 `hits` 为合并次数，`since` 保留最早时刻）；处理程序运行期间再次
  触发也只挂 1 位，完成后重入一次，不会无限重入。
- **电平线**：输入保持有效即反复可调度；处理完成的那个 tick 若电平仍有效，
  立即重新成为待处理位（下一 tick 可再次进入）。`lower` 撤销未消费的电平
  待处理位；`mask` 挂起调度但不撤销输入电平，`unmask` 时若电平仍有效则
  重新可调度（解除屏蔽本身不会合成边沿）。
- **屏蔽正在运行的线**不会杀掉其当前处理程序，只影响后续调度资格。

## 目录

```
src/model.ts          类型定义与排序规则
src/simulator.ts      核心状态机：ReplayController（step/advance）+ runReplay
src/scenarios.ts      预置演示
src/main.ts           回放页（时间轴 / 逐 tick 表格 / 日志三视图同源联动）
src/tests/reference-machine.ts  独立重写的逐 tick 参考状态机
src/tests/run-tests.ts          手写期望 + 批量等价 + 200 随机场景模糊测试
```

## 使用

```bash
npm install
npm test          # 运行测试（46 个断言，含参考状态机交叉核对）
npm run build     # 类型检查并打包到 dist/main.js
npm run serve     # 启动 http://localhost:8000 查看回放页
```

页面左侧编辑中断线与事件 JSON 后「载入并重放」，可用 单步 / +5 / 整批 三种
方式推进；点击时间轴格子、表格行或日志行可联动定位同一 tick。

## 测试如何核对

- **手写期望序列**：嵌套抢占、同优先级按 `since`+ID 等待、边沿屏蔽保留/
  重复合并、电平重入、电平屏蔽/解除、严格高优先级门槛、运行期边沿重入。
- **逐 tick 参考状态机**：`reference-machine.ts` 独立实现同一套语义，永远
  一次只推进 1 tick；被测实现分别以批次 1 / 2 / 3 / 5 / 11 / 一次性推进，
  逐 tick 比较完整快照（栈、待处理位、电平、屏蔽、动作、剩余 tick）。
- **模糊测试**：固定随机种子生成 200 个随机配置/事件场景，同样与参考机对齐，
  覆盖不同批次推进结果一致。
- **500 tick 上限**：持续有效的电平线无限重入，恰在 500 tick 截断并置
  `truncated` 证据。
